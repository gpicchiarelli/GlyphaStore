# ADR 0014: CRC32C for persistent integrity

- Status: accepted
- Date: 2026-07-19
- Owners: persistence maintainers
- Related: ADR 0008

## Context

Records, manifests, Segment headers, commit slots, and recovery intents need fast, portable
accidental-corruption detection with hardware acceleration on supported ARM64 and x86-64 systems.

## Alternatives considered

- CRC32 IEEE: widely known but not the selected hardware/storage polynomial;
- cryptographic hash or MAC: stronger but materially more expensive and requires a separate threat
  and key-management design;
- no checksum: rejected because corruption and torn metadata could become accepted authority.

## Decision

Use reflected CRC32C Castagnoli with polynomial `0x82F63B78`, initial value `0xFFFFFFFF`, final
complement, and the checksum field zero during calculation. Hardware instructions may accelerate the
same function; a portable compile-time table is the fallback. The ASCII test vector `123456789`
must produce `0xE3069283`.

## Consequences

CRC32C detects common accidental errors quickly and consistently across platforms. It does not
authenticate data and must not be described as protection against deliberate modification.
Implementations must avoid unaligned or aliasing-unsafe loads.

## Compatibility and verification

Changing parameters or checksum coverage changes the relevant persistent format. Every codec has
golden bytes, corruption tests, and hardware/fallback equivalence tests.
